\subsection*{A. Source, scope, and labeling}
This appendix documents the saved NYC DOT Street Condition request dataset: 70,322 rows and 38 columns, with one request per row and creation dates in 2025. Counts were checked against repository commit \texttt{d4a15bc} on October 22, 2026. CSV files do not preserve dataframe dtypes; the types below describe interpretation. The companion GitHub data dictionary and category inventory provide the same definitions and machine-readable counts.

The source is NYC Open Data, dataset \texttt{erm2-nwe9}, \emph{311 Service Requests from 2020 to Present}: \url{https://data.cityofnewyork.us/resource/erm2-nwe9.json}. Source field descriptions are available at \url{https://data.cityofnewyork.us/api/views/erm2-nwe9.json}. Python requests filtered the agency to DOT and the problem to Street Condition, using monthly creation-date windows from January 1, 2025 inclusive through January 1, 2026 exclusive. The automated helper requests ordered pages of 5,000 JSON records, preserves raw data, parses dates, and saves cleaned monthly CSVs.

The original 70,330 records became 70,324 after excluding six negative closure durations (February: 1; March: 2; July: 1; December: 2). The combined data had no duplicate request IDs. Two records with missing closure dates and Unspecified status were excluded from labeling. Recorded closure duration is the closure timestamp minus the creation timestamp, in hours. Dates are stored without timezone offsets, and the notebook uses timezone-naive subtraction; timezone and daylight-saving behavior should be confirmed before making precise elapsed-time claims.

The final target has 44,355 ones (63.1\%) and 25,967 zeros (36.9\%), with no missing labels. The 48-hour threshold is a team choice, not a verified city service standard or a measure of task difficulty. Closure means recorded administrative closure, not necessarily physical repair.

Labeling missing-closure Pending/Open requests as 0 assumes at least 48 hours of follow-up and sufficiently complete closure records. The 2025 requests were collected during the team's 2026 work, providing ample elapsed calendar time; record completeness remains an assumption. Missing-closure requests were retained, not all removed. Six Pending records have recorded closure times, so their labels follow the duration rule. There are 66,847 recorded durations, 3,475 missing durations, and 3,276 retained zero-hour durations. The live API changes, so later downloads need not reproduce this snapshot. Exact per-request retrieval times were not logged.

\subsection*{B. Column definitions}
The saved file contains both possible predictors and audit/outcome fields. Roles describe an initial proposal, not a final fitted matrix. Candidate fields require a submission-time availability check; geovalidated values may have changed since submission. Derive means use calendar features. Leakage means exclude outcome information from predictors. Audit, Constant, Empty, Sparse, and Redundant are excluded initially. Target is the response, not a predictor. No ordered severity categories are defined. Null counts refer to blank CSV cells, not literal Unknown or Unspecified values.

\subsection*{D. Derived features and modeling boundary}
The committed EDA notebook creates hour (0--23), month (1--12, January--December), day\_of\_week (Monday--Sunday), and location\_missing (True when latitude is absent, False otherwise) in memory. They are not additional columns in the saved 38-column CSV. Hour, month, and weekday have cyclical calendar interpretations rather than a street-condition severity order. The notebook replaces borough Unspecified with missing in its working copy. Coordinates are missing in 19,601 rows (27.9\%).

Weekend status and historical complaint-volume features discussed in the report remain planned; they are not created in the committed EDA notebook. If implemented, weekend denotes Saturday or Sunday. Historical counts must use only requests strictly earlier than the current request, specify the grouping and time window, and provide earlier history or an insufficient-history rule for the first window.

Exclude closed\_date, closure\_hours, status, resolution\_description, and resolution\_action\_updated\_date from predictors because they can reveal the outcome. Use closed\_48h only as the response. Retain unique\_key for audit, not prediction. Other initial exclusions are given in Table 2. Missing-value handling and encoding must be learned within the training pipeline. Unique IDs do not imply independence: requests can be related by place, time, or underlying incident. No final predictor matrix, validation split, trained model, or predictive performance is established by this documentation.
